# Diario de desarrollo — 2026-10-15

## Contexto

El ROADMAP hasta la Fase 4 estaba completamente marcado como finalizado (versión 0.9.0). El diario del 14 de octubre recomendaba documentar el contrato de la API y valorar autenticación más estricta. Se identificó como siguiente paso concreto de producto la posibilidad de descargar el dataset limpio tras aceptar el plan.

## Trabajo realizado

| Área | Detalle |
|------|---------|
| API | Nuevo endpoint `GET /datasets/{id}/cleaned.csv` que sirve el archivo generado por `apply_plan`. |
| Condiciones | Requiere que el plan esté aplicado; en caso contrario responde 400. |
| Aislamiento | Respeta el directorio por usuario: un usuario ajeno recibe 404. |
| Pruebas | Caso `test_download_cleaned_csv` que cubre el estado previo a la aceptación, la descarga exitosa y el aislamiento. |
| Documentación | Actualización de README, CHANGELOG (0.10.0), ROADMAP (Fase 5 iniciada) y versión del paquete. |

## Decisiones

- Se añadió una Fase 5 al ROADMAP para recoger mejoras de producto posteriores a la entrega base.
- Se priorizó la descarga del CSV limpio por ser una funcionalidad de uso inmediato y de bajo riesgo.
- Se mantiene el aislamiento existente sin introducir dependencias de autenticación adicionales.

## Resultado de validación

- `pytest` completo: todas las pruebas superadas (incluida la nueva).
- El propietario obtiene `text/csv` con el contenido esperado; un usuario distinto recibe 404.

## Próximo paso recomendado

Enriquecer la documentación OpenAPI (descripciones de endpoints y ejemplos) o implementar autenticación basada en API key si se requiere un control de acceso más formal.
