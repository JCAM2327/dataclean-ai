# Diario de desarrollo — 2026-10-22

## Contexto

Tras completar la estandarización en Fase 7, el ROADMAP no presentaba ítems pendientes adicionales. Se añade y completa la exposición del parámetro en la API como continuación natural de la preparación de características.

## Trabajo realizado

| Área | Detalle |
|------|---------|
| API | Parámetro de consulta opcional `scale_numeric` (bool, default false) en `POST /datasets` que se propaga a `analyze_frame`. |
| Pruebas | Nueva prueba `test_scale_numeric_parameter` verifica que el paso `scale_standard` no aparece por defecto y sí cuando el parámetro es verdadero. |
| Documentación | CHANGELOG (0.17.0), ROADMAP (ítem marcado y nueva Fase 8 propuesta), README, descripción del paquete y OpenAPI actualizados. |

## Decisiones

- El parámetro se expone como Query para mantener compatibilidad con el upload multipart existente sin alterar el esquema de archivo.
- Se mantiene el default en `False` para no cambiar el comportamiento de clientes existentes.
- Se abre Fase 8 para la codificación categórica como siguiente evolución lógica de la preparación de características.

## Resultado de validación

- La prueba de contrato confirma el control del paso de estandarización vía el parámetro de la API.
- La versión y las descripciones quedan consistentes.

## Próximo paso recomendado

Implementar codificación opcional de variables categóricas (one-hot o ordinal) en el plan de limpieza, con exposición correspondiente en CLI y API.
