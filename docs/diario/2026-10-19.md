# Diario de desarrollo — 2026-10-19

## Contexto

Tras completar el clipping de outliers IQR, el siguiente ítem pendiente de la Fase 6 es el soporte de formatos adicionales (Parquet y Excel) para ampliar la compatibilidad de entrada sin alterar el núcleo de perfilado y limpieza.

## Trabajo realizado

| Área | Detalle |
|------|---------|
| Carga | Nuevo módulo `dataclean.io` con `load_dataframe` que resuelve CSV, Excel (openpyxl) y Parquet (pyarrow) a partir de ruta o bytes. |
| CLI | Argumento renombrado a `file`; detección automática por extensión. |
| API | `POST /datasets` acepta las tres extensiones; validación temprana y mensajes de error claros. |
| Dependencias | `openpyxl` y `pyarrow` añadidos a `requirements.txt`. |
| Pruebas | Suite `tests/test_io.py` y nuevas pruebas de contrato en `tests/test_api.py` (Excel, Parquet, formato no soportado). Todas las pruebas existentes continúan pasando. |
| Documentación | CHANGELOG (0.14.0), ROADMAP (ítem marcado), README y versión del paquete actualizados. |

## Decisiones

- Se preserva el almacenamiento interno como CSV (`original.csv` / `cleaned.csv`) para no introducir complejidad en la persistencia ni en la descarga del resultado limpio.
- La detección se realiza exclusivamente por extensión; no se inspecciona el contenido binario.
- Se mantiene la descarga del resultado limpio únicamente en CSV, alineada con el contrato actual de la API.

## Resultado de validación

- 30 pruebas pasan, incluyendo las nuevas de carga y contrato de formatos.
- El esquema OpenAPI refleja el nuevo resumen y la descripción ampliada.
