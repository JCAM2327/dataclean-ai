# Diario de desarrollo — 2026-10-17

## Contexto

Tras completar la documentación OpenAPI enriquecida (0.11.0), el ROADMAP marcaba como único ítem pendiente la **Autenticación por API key (opcional)**.

## Trabajo realizado

|Área|Detalle|
|------|---------|
|API|Dependencia `get_user_id` ampliada para validar opcionalmente `X-API-Key` contra la variable de entorno `DATACLEAN_API_KEY`.|
|Seguridad|Si la clave está configurada, todos los endpoints protegidos exigen coincidencia exacta; de lo contrario se mantiene el comportamiento anterior.|
|Pruebas|Nuevas pruebas de contrato que verifican exigencia cuando está configurada e ignorancia cuando no lo está.|
|Documentación|CHANGELOG (0.12.0), ROADMAP (marcado como completado), README y versión del paquete actualizados.|

## Decisiones

- Se eligió una implementación basada en variable de entorno para mantener la opcionalidad sin introducir dependencias adicionales ni almacenamiento de claves.
- La validación se realiza en la misma dependencia que resuelve el usuario, garantizando que ambos controles se aplican de forma consistente.
- Se preservó el aislamiento existente por `X-User-Id` como mecanismo principal de multi-tenancy.

## Resultado de validación

- Las pruebas existentes continúan pasando.
- Las nuevas pruebas cubren los casos con y sin `DATACLEAN_API_KEY` configurada.

## Próximo paso recomendado

Con la Fase 5 completada, evaluar la necesidad de nuevas fases (por ejemplo, soporte para otros formatos de entrada, reglas de limpieza adicionales o mejoras de observabilidad) o consolidar el proyecto en su estado actual.
