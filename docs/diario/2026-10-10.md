# Diario de desarrollo — 2026-10-10

## Contexto

La fase 3 tenía completada la API de carga (0.5.0). El siguiente ítem del ROADMAP era la interfaz para revisar issues y aceptar el plan de limpieza.

## Trabajo realizado

| Área | Detalle |
|------|---------|
| Revisión | `GET /datasets/{id}/review` devuelve issues, plan, estado de aplicación y resumen. |
| Aceptación | `POST /datasets/{id}/accept` aplica el plan de forma explícita, actualiza el informe y expone el CSV limpio. |
| Almacén | Se retiene el DataFrame original y el objetivo declarado para permitir la aceptación posterior. |
| Contrato | Respuesta de carga incluye `review_url`. Aceptación repetida devuelve 409. |
| Pruebas | Ampliación de `tests/test_api.py` con casos de revisión, aceptación y conflictos. |

## Decisiones

- La interfaz se materializa como endpoints de API consumibles por un cliente (web o CLI), reutilizando `analyze_frame` con `apply=True`.
- No se añadió HTML estático: el contrato JSON es suficiente y consistente con el resto de la API.
- La persistencia permanece pendiente y no se mezcla en este entregable.

## Resultado de validación

- Pruebas de contrato de la API cubren el flujo de revisión y aceptación.

## Próximo paso recomendado

Persistencia de informes (almacén durable entre procesos).
