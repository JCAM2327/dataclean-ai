# Diario de desarrollo — 2026-10-14

## Contexto

El ROADMAP marcaba como pendiente el aislamiento de informes por usuario. Los módulos `api.py` y las pruebas de API eran placeholders; el resto del núcleo (perfil, plan, modelado, render HTML) estaba implementado.

## Trabajo realizado

| Área | Detalle |
|------|---------|
| Persistencia | Nuevo `dataclean.store.DatasetStore` con directorios por usuario (`data/users/{user_id}/datasets/{id}/`). |
| API | Implementación real de FastAPI: carga, consulta, aceptación del plan y exportación HTML. Cabecera obligatoria `X-User-Id`. |
| Aislamiento | Un usuario no puede leer ni modificar datasets de otro (404). |
| Pruebas | Contratos de autenticación mínima, aislamiento y aceptación de plan. |
| Corrección | Renderizado HTML tolera el número de clases como entero. |

## Decisiones

- Aislamiento por identificador de usuario en cabecera en lugar de autenticación completa (tokens, sesiones). Suficiente para el ítem del ROADMAP y sin dependencias adicionales.
- Reutilización de `analyze_frame` y `render_report_html` existentes.
- Versión 0.9.0 por tratarse de una funcionalidad nueva de acceso.

## Resultado de validación

- `pytest` completo: 16 pruebas superadas.
- El propietario accede a su informe HTML; un usuario distinto recibe 404.

## Próximo paso recomendado

Documentar el contrato de la API (OpenAPI ya disponible) y valorar autenticación basada en tokens o API keys si se requiere un control de acceso más estricto.
